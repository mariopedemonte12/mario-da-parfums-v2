# `fragrances` — notes

Owns: CRUD for the fragrance catalog (`name`, `brand`, `concentration`, `description`, `imageUrl`, `olfactoryFamily`, `targetAudience`, `longevity`). Admin-only — every route requires `Role.ADMIN`, including reads. Does not own populating the catalog (`perfumeCatalogImporter/`, a standalone Python import pipeline — see `specs/perfume-catalog-import.md`) or verifying `imageUrl` actually serves an image (separate job, outside this backend).

- **`olfactoryFamily`/`targetAudience`/`longevity`** (added by `specs/fragrance-notes-enrichment.md`): nullable `varchar`, exact-match filters in `GET /fragrances`, same pattern as `concentration` — deliberately **not** an enum despite each having a closed vocabulary on the importer side (`_AUDIENCE_MAP`/`_LONGEVITY_MAP`/`_CONCENTRATION_MAP` in `dataset_source.py`), for the same reason `concentration` isn't one either. As of this change, `perfumeCatalogImporter`'s own persistence path (`FragranceRepository.upsert()`, `CatalogSyncOrchestrator.run()`) is still an unimplemented stub — see that spec — so these columns are `NULL` for every row today; nothing populates them yet.

- **Mutations are batch-only** (`POST/PATCH/DELETE /fragrances/batch`), per `module-standards` — there are no single-item create/update/delete endpoints, only `GET /fragrances` (list) and `GET /fragrances/:id` (read). Batch responses are partial-success per item (`{ id, success, error? }`, or `{ success, id?, error? }` for create since the id doesn't exist until insert succeeds).
- **`imageUrl` validation is intentionally split** (agreed with the user, see `specs/fragrances-crud.md`): the DTO (`IsImageUrl`, `src/validators/is-image-url.validator.ts`) only checks that the value is a well-formed http(s) URL with an image extension — no network call. Actually confirming the URL serves a real image is done by a separate job outside this backend; this module does not fetch the URL itself. In practice `imageUrl` is currently always `null` — `perfumeCatalogImporter` populates the catalog from a static Kaggle dataset with no photos, not from scraping (see that spec for why scraping was dropped).
- `s3KeyImage` was removed from the schema in favor of `imageUrl` (plain `varchar`, nullable) — the photo was meant to come from webscraping, not an S3 upload flow, though no source for it exists yet (see above).
- No seed data yet: `fragrances` is FK-referenced by `listings`, but `listings`/`vendors` are still Nest CLI scaffolds and no seed runner exists anywhere in the project yet. Add fragrance seeds when `listings` is implemented and actually needs them.
- Swagger (`@nestjs/swagger`) wasn't wired into the project before this module; `main.ts` now sets up `SwaggerModule` at `/docs` as part of meeting the module-standards documentation bar.
