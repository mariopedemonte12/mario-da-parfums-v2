# `auths` — notes

- **Double check on duplicate email in `AuthsService.register`**: `findByEmail` first (optimistic check, avoids hashing work if the email is already taken), *and* the `usersService.create(...)` call is wrapped in a try/catch that maps Postgres unique-violation (`code === '23505'`) to `ConflictException`. The second check exists to cover the race between two concurrent registrations with the same email — without it, that race would surface as a generic 500 from an unhandled Postgres error instead of a 409.
- **Generic login error on purpose**: both "email doesn't exist" and "wrong password" return the same `UnauthorizedException('Invalid email or password')` — deliberately not distinguishing the two, so a failed login can't be used to enumerate registered emails.
- **`role` never comes from the client**: `RegisterDto` has no `role` field; `AuthsService.register` always forces `Role.USER` explicitly on create, so public registration can never self-assign `admin`. `RegisterDto`/`LoginDto` reuse the same `ValidationErrorCode`s as `CreateUserDto` (`src/users/dto/create-user.dto.ts`) for `name`/`email`/`password` — one source of truth for what those fields mean to the frontend, regardless of which endpoint they came through. `LoginDto` intentionally skips `@IsStrongPassword()` (login isn't the place to validate strength — that already happened at registration).
- **`JwtConfigModule` is separate from `AuthsModule`** and `@Global()`, so any future module needing to sign/verify tokens doesn't have to depend on `auths`. Uses `registerAsync` because `secret`/`expiresIn` come from `ConfigService`, which needs async resolution.
- **`login` returns `200`, not the `201` default for `POST`** (`@HttpCode(HttpStatus.OK)` in `AuthsController`) — a successful login doesn't create a resource.
- Follows the repo's error-handling convention (`docs/error-handling.md`): built-in Nest exceptions only, no custom hierarchy.
- **Test scope** (`auths.service.spec.ts`): the optimistic duplicate-email check is covered; the `code === '23505'` race-condition branch is not — no dedicated test for it in this file.
